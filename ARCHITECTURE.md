# Architecture

Four facts shaped this design. Each one cost real debugging time, and each is the reason for code
that would otherwise look arbitrary.

## 1. Reaching a live session requires being inside the process

The DSH HTTP carrier authenticates every Host RPC and WebSocket stream with the browser session
cookie. It accepts no query token and no `Authorization` header token outside the `GET /?token=...`
root exchange, so an outside process gets `401` and cannot call `session/prompt`.

Collabridge therefore runs as two halves:

- **host half** (`lib/index.js`): a Cordis plugin inside the trusted composition. It opens a loopback
  HTTP listener, writes a discovery file, and admits received questions into a session as inbound
  messages.
- **client half** (`lib/mcp-server.mjs`): an MCP stdio server that Codex spawns. It finds the host
  through the discovery file, authenticates with the token in it, and relays tool calls.

The discovery file is `$DSH_HOME/collab-bridge.json` and the audit log is
`$DSH_HOME/collab-bridge.log.jsonl`. The names predate the project rename and are kept deliberately:
the running host and existing tooling read them, and renaming them would split the record in two.
Both are rewritten whenever the host restarts, so a value read from them describes one moment only.

## 2. Injected messages must match the session format exactly

A session log is an append-only JSONL stream, compressed, and **generational**: older files are
`session.jsonl.zstd`, current ones `session.v4.jsonl.zstd`. Parsing must not assume one frame or one
shape, so `lib/session-log.mjs` owns that knowledge and everything else goes through it.

A message injected into a live session has to satisfy the same validator as a message the user typed.
Two details break naive implementations, and both were observed in production:

- Message sources are a closed map. A third-party producer must use the `plugin:<name>` kind; anything
  else is refused, and the session file stays empty. The failure surfaces far away, as a conversation
  that reports "this turn failed" with nothing at all written to disk.
- `id` and `role` must be present. The plugin mints them itself rather than trusting the caller.

## 3. A verdict is only a verdict if it is bound to a candidate

The identity of a review is not the reviewer's opinion, it is the tuple
`(package_id, nonce, candidate hash)`. The reviewer must echo `package_id` and `nonce` exactly. The
plugin hashes the candidate tree before and after the review and reports drift.

This is why the workflow script the reviewer runs is generated by the plugin rather than written by
the calling agent, and why identity is *bound* into that script instead of being transcribed by a
model. A model copying a long blob is not reliable, and one earlier design asked it to copy the
evidence itself; that produced a byte-for-byte mismatch on the first real package.

## 4. Whitespace at the ends of a script is not tampering

The generated script is transferred through a model and a JSON transport. Either can add a newline at
one end. Comparing byte for byte therefore threw away **three complete verdicts, in two projects**:
one leading `\n` and two trailing `\n`.

The comparison is now canonical: surrounding whitespace and a byte-order mark are ignored at the two
ends, the body must still be byte-identical, and anything inside the body (or appended after it) still
fails as an altered script with the first differing offset. Identity lives in the body, so tolerating
edge whitespace does not weaken the binding.

What was tolerated is recorded (`conductor_script_whitespace`) instead of being swallowed silently. A
guard that relaxes without saying so stops being a guard.

## Failure reporting

Both halves report failures as named states rather than exceptions, because the states are read by
agents that need to decide what to do next. The useful ones:

| State | Meaning |
|---|---|
| `REVIEW_WORKFLOW_NOT_CALLED` | The conductor never invoked the reviewer, so no verdict exists. |
| `REVIEW_CONDUCTOR_ALTERED_SCRIPT` | The script did not survive transfer intact, so the review cannot be bound to the intended request. |
| `REVIEW_CONDUCTOR_BAD_CALL` | The harness refused the call itself; no reviewer ran, no cost was incurred. |
| `REVIEW_RETURN_UNREADABLE` | The reviewer answered but the answer could not be extracted. |
| `REVIEWER_AGENT_FAILED` | The reviewer's provider or sandbox failed. |
| `MISSING_CREDENTIAL` | No usable model route on this device. |

Diagnosing "the plugin is broken" is usually three checks, in this order: which launcher mode was
used (`electron` for the current app packaging, `node` for an unpacked tree), which model route was
resolved, and whether telemetry came back empty (an empty telemetry block means the session root was
resolved to the wrong home, not that the review failed).

## Layout

```
lib/index.js          host half: listener, admission, audit
lib/mcp-server.mjs    MCP stdio server: ask_dsh, dsh_review
lib/review-bridge.mjs review orchestration: package validation, launcher resolution, verdict parsing
lib/session-log.mjs   session log reading across formats and generations
lib/routing.js        project/node/session resolution
lib/home.mjs          DSH home resolution
lib/budgets.mjs       cost and turn budgets
lib/cli.mjs           manual client for the host endpoint
cordis.patch.yml      the bundle patch that mounts the plugin
```
